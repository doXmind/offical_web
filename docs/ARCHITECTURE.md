# doXmind 架构决策记录 (ADR)

## 概述
本文档记录了doXmind官网开发过程中的重要架构决策，包括背景、决策理由和影响。

## ADR-001: 选择React + Vite作为技术栈

### 状态
已采纳

### 背景
需要选择适合快速开发和良好性能的前端技术栈。

### 决策
使用React 18 + Vite构建单页应用。

### 理由
1. React生态成熟，组件丰富
2. Vite构建速度快，开发体验好
3. 团队熟悉度高
4. 社区支持完善

### 后果
- 正面：开发效率高，性能优秀
- 负面：需要额外配置SEO优化

---

## ADR-002: 采用Tailwind CSS作为样式方案

### 状态
已采纳

### 背景
需要高效的样式解决方案，支持快速开发和一致的设计系统。

### 决策
使用Tailwind CSS作为主要样式框架。

### 理由
1. 原子化CSS提高开发效率
2. 易于保持样式一致性
3. 构建时自动清理未使用样式
4. 完美支持响应式设计

### 后果
- 正面：样式开发快速，文件体积小
- 负面：需要学习Tailwind类名体系

---

## ADR-003: 简化文件结构

### 状态
已采纳

### 背景
初始设计过于复杂，存在过度工程化问题。

### 决策
采用扁平化、简单的文件结构：
- pages/ - 页面组件
- components/ - 可复用组件（分3个子目录）
- core/ - 核心配置和工具
- assets/ - 静态资源

### 理由
1. 降低项目复杂度
2. 新开发者容易理解
3. 减少文件查找时间
4. 适合项目规模

### 后果
- 正面：维护简单，上手快
- 负面：大规模扩展时可能需要重组

---

## ADR-004: 黑白极简设计风格

### 状态
已采纳，最终版本为纯黑白设计 (见ADR-013)

### 背景
需要专业、现代的视觉风格，参考Anthropic等企业官网。

### 决策
- 主色调：纯黑白
- 无彩色强调色
- 设计原则：极简主义

### 理由
1. 突出内容，减少视觉干扰
2. 符合企业级产品定位
3. 提升可读性和专业感
4. 易于维护和扩展

### 后果
- 正面：视觉统一，专业感强
- 负面：需要通过布局和内容创造视觉兴趣

### 后续演进
2025-10-21升级为Purple Theme (ADR-010)
2026-01-13最终确定为纯黑白设计 (ADR-013)

## ADR-005: 单一数据源管理

### 状态
已采纳

### 背景
需要管理导航、功能列表、定价等静态数据。

### 决策
所有静态数据集中在 `core/constants.js` 文件中管理。

### 理由
1. 便于统一修改
2. 避免数据重复
3. 提高可维护性
4. 便于国际化扩展

### 后果
- 正面：数据管理清晰
- 负面：单文件可能变大

## ADR-007: 组件设计原则

### 状态
已采纳

### 背景
需要确定组件的设计和组织原则。

### 决策
1. 组件分三层：ui（原子）、sections（分子）、layout（模板）
2. 组件接收className prop支持样式扩展
3. 避免过度抽象

### 理由
1. 清晰的组件层次
2. 灵活的样式定制
3. 保持简单实用

### 后果
- 正面：组件职责清晰，复用性好
- 负面：需要规范执行

---

## ADR-008: 延迟路由实现

### 状态
已采纳，但实际提前完成

### 背景
需要决定何时实现页面路由。

### 决策
原计划将路由实现放在Phase 7，先完成所有页面开发。

### 理由
1. 降低初期开发复杂度
2. 专注于页面内容
3. 便于调整页面结构
4. 路由实现相对简单

### 后果
- 正面：开发顺序更合理
- 负面：开发期间页面切换不便

### 实际执行
在Phase 3 (Features页面开发) 时提前集成React Router，因为多页面导航需求已经出现。参见ADR-011。

### 状态
已废弃 (被ADR-013取代)

## ADR-011: React Router早期集成

### 状态
已采纳

### 背景
原计划Phase 7再集成路由，但在Phase 3开发时发现多页面导航需求已迫切。

### 决策

### 后果
- 正面：开发体验和用户体验同步提升
- 负面：比原计划提前，增加Phase 3复杂度

### 实施日期
2025-07-29

## ADR-012: Beta-First内容策略

### 状态
已采纳

### 背景
初期官网包含大量虚假内容（假统计数据、假下载、假定价），不利于建立信任。

### 决策
- 移除所有虚假内容和占位符
- 强调Beta测试计划
- 所有CTA改为"Launch App"链接到真实Beta环境
- 简化Pricing为免费Beta访问
- 清理Footer虚假链接

### 理由
1. 建立真实可信的品牌形象
2. Beta测试是当前真实状态
3. 避免误导用户
4. 符合产品发展阶段

### 后果
- 正面：内容真实可信，用户信任度提升
- 负面：页面内容相对简化

### 实施日期
2025-10-21

---

## ADR-013: 纯黑白品牌设计

### 状态
已采纳

### 背景
需要统一品牌形象，采用新的品牌设计规范。

### 决策
- 主色调：纯黑 (#000000)
- 次要色：纯白 (#FFFFFF)
- 无彩色强调色 - 完全黑白设计
- Logo：X形四象限设计，圆角
- 品牌字体："doXmind"
  - "do" 和 "mind"：font-weight 300 (light)
  - "X"：font-weight 900 (black)
  - letter-spacing: -1.5px

### 理由
1. 极简主义美学，更加专业
2. 强化品牌辨识度
3. 与内容形成更好对比
4. 减少视觉干扰

### 后果
- 正面：品牌形象统一，设计简洁
- 负面：需要更新所有组件和文档

### 实施日期
2026-01-13
